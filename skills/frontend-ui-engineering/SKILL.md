# Frontend UI Engineering

## Overview

Build production-quality user interfaces that are accessible, performant, and visually stunning. This skill combines architectural rigor (component composition, state layering, semantic HTML) with **deterministic design intelligence** — a searchable database of 79 UI styles, 192 product reasoning profiles, 192 curated palettes, 74 typography pairings, 119 UX guidelines, 25 chart specs, and 22 framework-specific implementation stacks.

The goal is UI that looks like it was designed by a world-class product designer and built by a senior frontend engineer — never like it was generated by a generic AI.

## When to Use

- Designing or building new UI pages, screens, or components
- Establishing or extending a product design system
- Modifying existing user-facing interfaces or fixing layout bugs
- Selecting color palettes, typography pairings, or motion tiers
- Meeting WCAG 2.1 AA accessibility standards (contrast, focus, keyboard nav)
- Implementing responsive layouts across desktop and mobile

**When NOT to use:** Backend-only changes with no user-facing surface, non-visual CLI tools, or infrastructure scripts that render no UI.

## Design Intelligence Engine (Local Querying)

This skill ships with an embedded, zero-dependency Python search engine (`scripts/search.py`) powered by BM25 ranking and regex filtering. Always use the search tool instead of guessing styles, hex codes, or fonts.

### Invocation

```bash
# Query specific design domains
python skills/frontend-ui-engineering/scripts/search.py "<query>" --domain <domain>

# Or use the workspace root shortcut
./scripts/ui-search.sh "<query>" --domain <domain>
```

**Available Domains:**
- `product`: Product type recommendations and layout structures (SaaS, FinTech, E-commerce, Healthcare, Media)
- `style`: 79 UI styles (glassmorphism, bento grid, neo-brutalism, minimal flat, dark modern) + CSS keywords
- `color`: 192 curated 5-token palettes (primary, secondary, accent/CTA, background, text/foreground)
- `typography`: 74 font pairings with mood descriptions and Google Fonts import URLs
- `landing`: High-converting page structures and CTA placement strategies
- `chart`: 25 chart recommendations, volume thresholds, and library advice (Recharts, Chart.js, D3)
- `ux`: 119 UX guidelines, WCAG criteria, touch target sizes, and anti-patterns
- `icons`: Icon search for Lucide, Heroicons, and Phosphor
- `stacks`: 22 framework recipes (`html-tailwind`, `react`, `nextjs`, `shadcn`, `vue`, `svelte`, `swiftui`, `flutter`, `react-native`, `jetpack-compose`, etc.)
- `motion`: 17 GSAP & CSS motion presets organized by intensity tiers (hover, reveal, stagger, transition)

### Full Design System Generation

For new features, pages, or projects, generate a cohesive design system:

```bash
python skills/frontend-ui-engineering/scripts/search.py "<product_type> <keywords>" --design-system [-p "Project Name"]
```

**Design Dials (1-10 tuning sliders):**
- `--variance <1-10>`: 1 = centered/minimal, 10 = bold/asymmetric
- `--motion <1-10>`: 1 = subtle micro-interactions, 10 = complex GSAP choreographed sequences
- `--density <1-10>`: 1 = spacious/editorial, 10 = dense data-rich dashboard

**Master + Overrides Persistence:**
Persist the generated design contract to `.agents/design-system/`:

```bash
python skills/frontend-ui-engineering/scripts/search.py "<query>" --design-system --persist -p "Project Name" --output-dir .
```
This generates:
- `.agents/design-system/<project-slug>/MASTER.md` — Global Source of Truth
- `.agents/design-system/<project-slug>/pages/<page-slug>.md` — Optional page-level overrides (`--page <name>`)

## Rule Categories by Priority (1 → 10)

Follow this strict priority order when making visual and interaction decisions. The complete list of all 119 UX rules lives in [quick-reference.md](references/quick-reference.md).

| Priority | Category | Impact | Domain | Key Checks (Must Have) | Anti-Patterns (Avoid) |
|:---:|---|:---:|:---:|---|---|
| **1** | **Accessibility** | CRITICAL | `ux` | Contrast ≥ 4.5:1 (3:1 large text), visible focus rings, aria-labels on icon buttons, keyboard traps prevented | Removing `:focus-visible` outline, icon-only buttons without accessible labels |
| **2** | **Touch & Target** | CRITICAL | `ux` | Min touch target 44×44px, ≥8px spacing between targets, instantaneous feedback on tap | Hover-only interactions on mobile, tiny hitboxes |
| **3** | **Performance & CLS** | HIGH | `ux` | Reserve image/video aspect ratio (CLS < 0.1), WebP/AVIF formats, skeleton loaders | Layout shift on data arrival, full-page blocking spinners |
| **4** | **Style Coherence** | HIGH | `style`, `product` | Pick style matching product archetype, use SVG icons (Lucide/Heroicons), maintain border-radius scale | Mixing flat and skeuomorphic randomly, using emojis as UI icons |
| **5** | **Layout & Responsive** | HIGH | `ux` | Mobile-first breakpoints (375px, 768px, 1024px, 1440px), safe areas (`env(safe-area-inset-*)`), no horizontal scroll | Horizontal scrollbars on mobile, fixed pixel container widths |
| **6** | **Typography & Color** | MEDIUM | `typography`, `color` | Base font ≥ 16px body, line-height 1.5, semantic design tokens (`--color-primary`, `--color-background`) | Body text < 12px, gray-on-gray unreadable text, hardcoded raw hex colors in components |
| **7** | **Animation & Motion** | MEDIUM | `ux`, `motion` | Context-aware timing (150-300ms), spatial continuity, respect `prefers-reduced-motion` | One duration for all transitions, animating layout properties (`width`/`height`), 0ms jarring cuts |
| **8** | **Forms & Validation** | MEDIUM | `ux` | Explicit persistent labels, inline error messages near field, helper text, accessible validation | Placeholder-only inputs, hiding errors at the top of long forms |
| **9** | **Navigation** | HIGH | `ux` | Predictable back behavior, bottom navigation ≤ 5 destinations, active state indication | Overcrowded menus, breaking browser back button, missing active indicator |
| **10** | **Data Visualization** | LOW | `chart` | Legends, tooltips, colorblind-safe palettes, keyboard accessible data tables | Using color as sole indicator of status or chart value |

## Component Architecture

### File Colocation

Colocate everything related to a component in a dedicated folder:

```
src/components/
  TaskList/
    TaskList.tsx          # Component implementation
    TaskList.test.tsx     # Unit & interaction tests
    TaskList.stories.tsx  # Storybook stories (if applicable)
    use-task-list.ts      # Custom hook (complex logic/state)
    types.ts              # Component-specific types
```

### Component Patterns

**Prefer composition over configuration:**

```tsx
// Good: Composable, clear hierarchy
<Card>
  <CardHeader>
    <CardTitle>Tasks</CardTitle>
  </CardHeader>
  <CardBody>
    <TaskList tasks={tasks} />
  </CardBody>
</Card>

// Avoid: Massive config objects with rigid layout assumptions
<Card
  title="Tasks"
  headerVariant="large"
  bodyPadding="md"
  content={<TaskList tasks={tasks} />}
/>
```

**Keep components focused and single-purpose:**

```tsx
// Good: Presentation component doing one thing cleanly
export function TaskItem({ task, onToggle, onDelete }: TaskItemProps) {
  return (
    <li className="flex items-center gap-3 p-3 rounded-lg border border-border bg-card">
      <Checkbox checked={task.done} onCheckedChange={() => onToggle(task.id)} />
      <span className={task.done ? 'line-through text-muted-foreground' : 'text-foreground'}>
        {task.title}
      </span>
      <Button variant="ghost" size="icon" aria-label="Delete task" onClick={() => onDelete(task.id)}>
        <TrashIcon className="h-4 w-4" />
      </Button>
    </li>
  );
}
```

**Separate data fetching from presentation:**

```tsx
// Container: handles async query, error, loading states
export function TaskListContainer() {
  const { tasks, isLoading, error, refetch } = useTasks();

  if (isLoading) return <TaskListSkeleton />;
  if (error) return <ErrorState message="Failed to load tasks" retry={refetch} />;
  if (!tasks?.length) return <EmptyState message="No tasks yet" actionLabel="Create Task" />;

  return <TaskList tasks={tasks} />;
}

// Presentation: pure renderer, easily testable and storybook-ready
export function TaskList({ tasks }: { tasks: Task[] }) {
  return (
    <ul role="list" className="space-y-2">
      {tasks.map(task => <TaskItem key={task.id} task={task} />)}
    </ul>
  );
}
```

## State Management

Choose the simplest layer that solves the problem:

```
Local state (useState)           → Ephemeral component UI state (open/closed, focused)
Lifted state                     → Shared between 2-3 sibling components
Context                          → Read-heavy, write-rare global values (theme, locale)
URL state (searchParams)         → Filters, pagination, tab selection, search query
Server state (React Query, SWR)  → Remote data with caching, revalidation, deduping
Global store (Zustand)           → Complex client state shared across disconnected trees
```

**Rule:** Avoid prop drilling deeper than 3 levels. Introduce URL state or context when props traverse intermediate components that do not consume them.

## Eliminating the "AI Aesthetic"

AI models default to repetitive, generic design habits. Actively eliminate them:

| AI Default | The Problem | Production Standard |
|---|---|---|
| **Purple/Indigo gradients** | Identical visual fingerprint across all AI generated sites | Derive colors from the industry archetype via `scripts/search.py "<industry>" --domain color` |
| **`rounded-2xl` everywhere** | Obliterates hierarchy; makes enterprise tools look like toys | Strict border-radius tokens: `sm` (2-4px) for controls, `md` (6-8px) for cards |
| **Heavy layered box shadows** | Renders muddy and slow on mobile GPUs | 1px border (`border-border`) with subtle 1-layer shadow or clean flat elevation |
| **Emojis as icons (🚀, 🔥)** | Inconsistent rendering across OSs, no color inheritance | Clean SVG icons via Lucide, Heroicons, or Phosphor |
| **Stock uniform 3-card grids** | Disregards information hierarchy | Purpose-driven layouts (bento grids, split hero, list-detail) |
| **0ms instant state flips** | Jarring interaction cuts | 150-200ms ease-out transitions on hover/focus |

## Pre-Delivery UI Polish Checklist

Before declaring any frontend work complete, verify every item. For comprehensive checklist details, refer to [pro-rules.md](references/pro-rules.md).

- [ ] **Accessibility (WCAG 2.1 AA)**:
  - [ ] Text contrast verified ≥ 4.5:1 against its immediate background in **both** light and dark themes
  - [ ] Focus rings visible when navigating via keyboard (`:focus-visible` styled)
  - [ ] All interactive elements reachable and operable via Tab, Enter, Space, and Escape
  - [ ] Icon-only buttons have descriptive `aria-label`
- [ ] **Touch & Mobile**:
  - [ ] Hit areas are at least 44×44px with ≥8px spacing
  - [ ] Safe areas respected on iOS (`pb-safe`, `pt-safe` or `env(safe-area-inset-*)`)
  - [ ] No horizontal scroll at 375px viewport
- [ ] **Motion & Polish**:
  - [ ] Smooth transitions on interactive states (150-250ms)
  - [ ] `@media (prefers-reduced-motion: reduce)` respected (animations disabled or instant)
  - [ ] Cursor set to `cursor-pointer` on all clickable non-button elements
- [ ] **The "SEE IT" Gate**:
  - [ ] The developer/agent has visually inspected the rendered output at 375px, 768px, and 1440px in all states: loading, empty, error, and populated.

## Common Rationalizations

| Rationalization | Reality |
|---|---|
| "This is just an internal dashboard, contrast doesn't matter" | Low contrast causes eye strain and errors for real users. 4.5:1 is a basic quality bar. |
| "I'll add responsive styles in a follow-up PR" | Retrofitting responsive layouts is 3x harder than mobile-first scaffolding from step one. |
| "A generic gradient makes the app look modern" | It screams "AI generated prototype". Curated palettes with proper CTA hierarchy build user trust. |
| "Tests pass, so the UI is good" | Tests only check DOM structure, not whether a button is clipped or unreadable. The "SEE IT" gate is mandatory. |

## Red Flags

- Hardcoded arbitrary pixel spacing (`p-[13px]`, `mt-[27px]`) instead of design system scale
- Raw hex codes scattered throughout component styles
- Icon buttons missing `aria-label`
- Removing outline on focus (`outline-none` without replacement)
- Missing empty or error states (rendering empty white boxes on failed network calls)
- Relying exclusively on color to convey error or status (must include text or icon)

## Verification

After building or modifying any UI:

- [ ] Component renders without console errors or warnings
- [ ] All interactive elements are keyboard accessible (Tab / Enter / Space)
- [ ] Responsive behavior verified at 375px, 768px, 1024px, 1440px
- [ ] Loading, empty, and error states explicitly handled
- [ ] Color tokens and typography conform to `.agents/design-system/MASTER.md`
- [ ] Passes Pre-Delivery UI Polish Checklist with zero violations
